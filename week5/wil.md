## Java : 객체 지향 언어

- 스프링 : Java 기반 **프레임워크**

스프링은 Java의 가장 큰 특징인 **객체 지향**을 잘 살려내서, **좋은 객체 지향 프로그램을 개발할 수 있도록** 도와주는 **프레임워크**

## 객체 지향 프로그래밍(OOP)

- 모든 것을 부품처럼 독립적으로 잘게 쪼개서 레고 블럭 조립하듯 전체 프로그램을 완성(**객체들의 상호작용**이 중요시)

객체 지향 프로그래밍은 **유연**하고 **변경**이 용이하기 때문에, 현업에서 많이 사용된다.

### 객체 지향의 네 가지 특징

1. 추상화 : 객체의 **공통적인** 속성 & 기능을 추출하고 정의
2. 캡슐화 : 서로 연관있는 속성 & 기능을 하나의 **캡슐**로 만들어 데이터를 외부로 **보호**
3. 상속 : 기존 클래스의 속성 & 기능을 새로운 클래스가 상속받아 **재사용**
4. 다형성 : 어떤 객체의 속성이나 기능이 상황에 따라 **여러 가지 형태**로 바뀜
    - 어떤 **역할**에 대해 여러가지 **구현 방식**이 존재

### 다형성이 백엔드에서 중요하다.

클라이언트는 대상의 역할만 알면 되고, 실제 구현은 알 필요가 없다. 그리고 내부 구현이 변해도 영향을 받지 않는다.

→ 다형성은 프로그램을 유연하고, 변경에 용이하게 해준다!

이를 우리가 만든 쇼핑몰 코드에 적용해보자!

- 역할을 만들어 놓고, 그 역할을 수현하는 구현체를 **바꿔** 끼자!



HOW?

- 역할 → 인터페이스
- 구현 → 인터페이스를 구현할 클래스

## SOLID 원칙

좋은 객체지향 설계를 위한 5가지 원칙

- SRP : 단일 책임 원칙 : 하나의 클래스 단 한개의 책임을 가져야 함.
- OCP : 개방-폐쇄 원칙 : 클래스는 확장에 열려있고, 수정에 닫혀 있어야 함.
- LSP : 리스코프 치환 원칙 : 자식 클래스는 언제나 부모 클래스를 대체할 수 있어야 함.
- ISP : 인터페이스 분리 원칙 : 인터페이스를 잘 분리해야 함.
- DIP : 의존관계 역전 원칙 : 추상화에 의존해야 함(Not 구체화)

### 다형성만으로는 SOLID 원칙을 지킬 수 없어서 스프링은 의존성 주입(Dependency Injection)을 지원한다.

## IoC(Inversion of Control) : 제어의 역전

객체 생성 및 관리에 대한 제어권을 개발자가 아닌 프레임워크가 대신 가져가는 것

- 스프링 컨테이너를 IoC 컨테이너라고 한다.

### Spring Container

스프링 빈 저장소

### Spring Bean & Spring Container

어플리케이션 전역에서 사용할 **공용 객체**(스프링 컨테이너가 관리)

### 싱글톤 컨테이너

스프링 컨테이너는 객체를 딱 **한개**만 생성해서 필요할 때마다 재사용하게 함.
